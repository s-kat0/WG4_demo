# WG4講演デモ 簡易手順（講演者向け）

対象アプリ：<https://wg4-demo-kato.streamlit.app/>

参加者への配布資料は[participant_guide.md](participant_guide.md)を使用する。このファイルは登壇中の進行確認用であり、Secretsや管理操作は記載しない。

## 事前確認

1. 新しいブラウザセッションで参加者ログインする。
2. `知識を探す`で、初期知識が12件（文書6件、Q&A 6件）あることを確認する。
3. サイドバーで`gpt-5.6-luna`、reasoning `medium`、KB改訂1を確認する。
4. API処理中は画面の`待機中`・`実行中`表示を待ち、同じボタンを押し直さない。

## 導入：初期知識を探す

1. `知識を探す`を開く。
2. `冷却器1 流量低下`で検索する（API不使用）。
3. 文書またはQ&Aを一つ開き、`原文と版を確認`を見せる。

説明：既に蓄積された12件へ、これから一つの冷却器1事例を追加する。

## デモ①：文書を登録する（スライド6）

1. `知識を追加・補足する`を開く。
2. 入力済みの保全記録1で`文書から知識候補を抽出（APIを使用）`を押す。
3. 未承認カードと原文を照合し、次を確認する。
   - 出口温度表示が高めになったこと
   - 別の計器と突き合わせたこと
   - 原因は未特定で、判断理由・適用範囲がまだ不足していること
4. `文書だけで承認候補を作る（API不使用）`を押す。
5. `更新案・実回答比較`の`人の確認待ち`で差分・原文・未確認事項を確認する。
6. 確認欄を選び、`確認してv1として承認`を押す。
7. `空の会話で回答Aを実行（APIを使用）`を押し、文書だけの回答Aを保存する。

見るポイント：記録された行動と、まだ分からない理由・条件が区別されているか。

## デモ②：理由と適用条件を聞く（スライド9）

1. `知識を追加・補足する`へ戻る。
2. 入力済みの本人役の開始発言で`不足情報を一つ質問（APIを使用）`を押す。
3. LLMが生成した追加質問を読み、質問に合う本人役の回答を確認して`回答して次の質問へ（APIを使用）`を押す。
4. 判断理由と適用範囲がそろうまで、目安として二往復する。回数だけで完了を判断しない。
5. `ここまでの聞き取りで補足案を作る（APIを使用）`を押す。
6. `更新案・実回答比較`で、追加された理由・条件と本人役の発言を照合する。
7. 確認欄を選び、`確認してv2として承認`を押す。

説明：画面へ自動入力される本人役の回答例は固定の架空教材であり、LLM生成ではない。LLMが生成するのは追加質問である。

見るポイント：文書になかった理由・適用条件が、本人役の発言を出典として追加されているか。

## デモ③：追加した知識を回答に使う（スライド14）

1. `更新案・実回答比較`で`空の会話で回答Bを実行（APIを使用）`を押す。
2. 保存済みの回答A/Bを開き、同一条件の実回答比較であることを確認する。
3. 回答Bで次を確認する。
   - 本人役が述べた判断理由
   - 温度計交換直後、冷却水流量・入口温度が通常範囲という適用条件
   - 参照した知識項目と版
   - 本人役の発言を含む原文の根拠
   - `search_knowledge → get_context → read_evidence`の実行履歴
4. 時間に余裕があれば`エージェントに相談する`で新しい会話を開始し、一問だけ追質問する。

追質問例：`流量が下がっていた場合も、同じ確認でよいですか。`

見るポイント：回答の言い換えではなく、新しく追加したfactと出典が根拠として使われたか。

## デモ④：修正を次の相談に残す（スライド17）

1. `更新案・実回答比較`の`回答Bの実候補へ条件を一つ補足`を開く。
2. 次の発言で`根拠・条件の更新案を作る（APIを使用）`を押す。

   > 照合用の計器も、校正が有効か確認する必要があります。

3. `人の確認待ち`で、現行v2から新版v3への差分と新しい原文を確認する。
4. 確認欄を選び、`確認してv3として承認`を押す。
5. `空の会話で回答Cを実行（APIを使用）`を押す。
6. B/Cを比較し、Cで校正の有効性を確認する条件と`聞き取り記録2`が新たに参照されたことを確認する。
7. `エージェントに相談する`で`新しい会話（知識は残す）`を押し、新しい会話の最初に次を入力する。

   > 冷却器1の出口温度の表示が高い。温度計交換直後で、冷却水流量と入口温度は通常範囲。何を確認するか？

8. `知識項目13 v3`、校正条件、`聞き取り記録2`が参照されることを確認する。

説明：追加したのは「校正が有効か確認する」という行動前提であり、「実際に校正が有効だった」という観察ではない。

見るポイント：会話履歴ではなく、人が承認して保存した新版が新しい会話でも参照されるか。

## A/B/Cの意味

| 回答 | 知識版 | 比較する内容 |
|---|---:|---|
| A | v1 | 文書に記録された行動・条件 |
| B | v2 | 本人役が補った判断理由・適用範囲・出典 |
| C | v3 | 校正の有効性を確認するという追加条件・出典 |

## 障害時

- エラー時は同じ操作を再送せず、画面のエラーコードと操作IDを記録する。
- A/B/Cの失敗後に専用の再実行ボタンが表示された場合も、原因確認後に講演者が明示的に開始する新規操作として扱う。
- 検索0件と検索失敗を混同しない。
- 録画へ切り替える場合は「記録の再生」と明示し、アプリの代替回答として扱わない。
- デモ後はスライド番号ではなく、次の「全体像に戻る」スライドへ戻る。
