# v5追加受入テスト

本書は既存テストへ追加・変更する仕様であり、アプリでの実施結果ではない。通常CIは外部通信を禁止し、モックと決定的処理で検査する。実APIとCloudは別の明示的な検証として記録する。

## A. 初期知識・検索

| ID | 操作 | 合格条件 |
|---|---|---|
| SEED-01 | 新規v5領域を作成 | 独立したKnowledgeItemが12件、文書6件/Q&A6件。fact数で代用しない |
| SEED-02 | 全件の根拠を読む | 12出典の全文、segment、quoteが解決でき、引用が原文の部分文字列 |
| SEED-03 | Q&Aのfactを検査 | 根拠は本人役の回答。質問文だけを観察・理由の証拠にしない |
| SEED-04 | 同じworkspaceへ二重初期化を要求 | 二重登録しない。明示的な新領域以外へ差し込まない |
| SEED-05 | 再ログイン・cache破棄・DB消失 | 既存データを同じ領域へ黙ってseedで置換しない。台帳も復元しない |
| SEED-06 | 壊れたquote/重複key/不正scope | 一部登録を成功扱いせず拒否する |
| SEED-07 | ターゲット追加入力をまだ送らない | 保全記録1・詳しい切り分け理由・校正条件が初期検索やpromptに入らない |
| SEED-08 | 旧形式workspaceを開く | 旧知識項目3・各版・履歴が変わらず、初期12件を勝手に足さない |
| SEARCH-01 | `冷却器1 流量低下` | seed-k02またはseed-k08を関連候補として取得し、原文へ戻れる |
| SEARCH-02 | `起動直後の記録を別に探す理由` | seed-k04またはseed-k10を取得し、運転区分を示す |
| SEARCH-03 | `清掃履歴 原因` | seed-k09を取得し、原因を断定する根拠とは扱わない |
| SEARCH-04 | `ポンプ1 振動` | seed-k05/11を取得。冷却器の事例を同設備として示さない |
| SEARCH-05 | `貯槽1 液位 設計` | seed-k06/12を取得。制御器設定値を作らない |
| SEARCH-06 | 設備・由来フィルター | 結果件数と原文が実DBに対応し、別workspaceを含まない |
| SEARCH-07 | 一覧・原文・グラフを繰り返し表示 | 実API呼出し0、知識と台帳の書換えなし |
| SEARCH-08 | 検索0件／検索例外 | 前者は正常0件、後者はfailed。型と画面で区別 |

## B. 対話

| ID | 操作 | 合格条件 |
|---|---|---|
| CHAT-01 | 初期12件のまま相談 | 文書登録・対話補足を終えなくても相談できる |
| CHAT-02 | `冷却器1の出口温度の表示が高い` | 知識検索と不足条件の確認。交換直後や流量通常を未入力のまま補わない |
| CHAT-03 | 次に交換直後・流量/入口温度通常を回答 | user入力を現在相談条件として扱い、現行知識を再検索。無承認で永続知識にしない |
| CHAT-04 | `なぜこの確認をするのですか` | 前の対象を保持し、その理由と原文を読む。候補1位強制だけを理由に失敗しない |
| CHAT-05 | 理由が記録されていない対象に理由を尋ねる | 理由の記録不足を伝え、過去の本人発言を代作しない |
| CHAT-06 | `どの記録に書いてありますか` | 実取得済みの原文・出典を示す |
| CHAT-07 | `流量が低かった場合も同じですか` | 仮定の別条件として再検索。現在の観測事実を黙って訂正しない |
| CHAT-08 | `訂正します。実際には流量が低かったです` | 現在相談の訂正として扱い、変更した前提を表示する |
| CHAT-09 | ポンプ1へ話題変更 | 冷却器1の設備・条件を引き継がず、必要な確認をする |
| CHAT-10 | 曖昧な`それ`で参照候補が複数 | 対象を確認する。任意の候補へ決め付けない |
| CHAT-11 | 会話中にKBの承認版が変わる | 新ターンでは再取得。過去回答を最新根拠にしない |
| CHAT-12 | 根拠不整合・未取得ID・他workspace | 追質問でも検証拒否し、似たIDへ補正しない |

## C. 四段階・比較

| ID | 操作 | 合格条件 |
|---|---|---|
| FLOW-01 | 文書単独で承認 | 通常の新規v5領域では13件目。対話なしでも保存可能で不足を残す |
| FLOW-02 | 既存文書版へ聞き取り | 項目数は増やさず、その項目の新版を作る。対象を3や13で固定しない |
| FLOW-03 | 観察条件を冒頭で提示 | 既に答えた条件を儀式的に再質問せず、理由・範囲の不足へ進む |
| FLOW-04 | 理由・範囲・例外を本人役が回答 | 対応するfactと原文を保持。原因未確定を変えない |
| FLOW-05 | 理由を`覚えていない`と回答 | 不明を保持。成功演出のための補完なし |
| FLOW-06 | 対話更新がpending | 通常検索・原文ツール・他のQAに新発言が混入しない |
| FLOW-07 | 同じ質問トピックを言い換えて再生成 | structured output検証で拒否し、重複質問を表示しない。別回答を自動送信しない |
| FLOW-08 | 理由・適用範囲・例外が回答済み | LLMは聞き取り完了を返せる。固定回答例を3回目以降に自動挿入しない |
| UI-09 | 聞き取りの質問と回答例を表示 | 追加質問はLLM生成、開始発言・本人役回答例は固定収録教材でLLM生成ではないと明示 |
| CMP-01 | 文書版A・対話版Bを比較 | 同じ質問、model/prompt/検索設定、両方空履歴、実回答と参照版を記録 |
| CMP-02 | Bで追加情報を利用 | 追加理由・範囲が実際の新fact/segmentに結び付く。文章の長さだけを成功基準にしない |
| CMP-03 | 新情報を読まないB | 結果と取得ログをそのまま記録し、改善を捏造しない |
| CMP-04 | Aがない／Bがfailed | 実行記録なし／failedを示す。期待文や過去の別回答を入れない |
| CMP-05 | モデル・prompt・質問・履歴が違う | 純粋な知識更新比較として表示せず、参考比較と明示 |
| CMP-06 | 低順位の適合候補を理由説明等で扱う | 一律の1位強制ではなく、対象・根拠・条件の検証で受理/拒否する |
| FB-01 | Bの候補からフィードバック | 実answer ID、知識item、取得版、現在版、新発言を正しく引き継ぐ |
| FB-02 | 校正条件を承認 | 行動前提を追加し、校正済みの過去観測へ変えない |
| FB-03 | 空履歴のCを実行 | 新版・新出典を実際に取得。A/Bの会話内容から再現しない |
| FB-04 | A/B/Cを表示 | 初期知識件数、各版、取得根拠が分かる。過去の実記録だと明示 |

## D. 回帰と負荷

旧ハンドオフの認証・所有権・台帳・キュー・取消・遅着・保存・フォールバック禁止のテストを維持する。新しい検索画面、対話、比較経路も対象にする。

- 初期12件を各30sessionへ分離して持たせ、一覧閲覧と質問投入で知識や出典が混ざらない。
- 同時job3・待機30・sessionあたりactive1が新画面でも機能する。
- 入力待ち・原文閲覧でワーカー枠を保持しない。
- `provider_hard_limit`では全体・session別call枠なしで監査記録が増え、操作別・RPM/TPM・同時実行上限は維持される。
- `finite`互換モードではsession40call・全体600call等が、再比較や新会話で戻らない。
- 模擬の遅いAPI、API例外、検索例外、保存例外、DB消失、二重クリックを試す。
- keyword検索とLLM相談の両経路で、未承認・旧版・他workspaceが混ざらない。
- promptに初期12件全体や未送信のデモ回答が無条件に投入されない。

## E. 実API・Cloudでの報告

実APIは運営者が許可し、OpenAI projectのhard limit、live gate、台帳、利用期限等が満たされた場合だけ行う。主シナリオと代表的な追質問を複数回試し、必須の根拠保持と自然な対話を人が確認する。未通過を固定回答で隠さない。文言一致は求めない。

ローカルmock、ローカル実API、Cloudの実ブラウザ、Cloudの実API負荷を別に記載する。旧版の所要時間やcall数をv5の実績に流用しない。本番の二往復・比較・追質問を含む合計の時間と利用量を新たに測る。
