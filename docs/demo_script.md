# 約6分の講演デモ

## 前半 1分30秒

1. 「最初から体験」でログインし、保全記録1を抽出。
2. 出口温度表示上昇、交換直後、独立計器との照合、原因未確定と原文の対応を表示。
3. 経験談から追加質問を生成。
4. 「冷却水の流量と入口温度は、どちらも通常の範囲でした」と回答。
5. pendingカードを確認し、知識項目3 v1として人が承認。

## 後半 4分30秒

1. 主質問を送信し、検索→グラフ探索→原文取得の実行記録を表示。
2. 独立計器との照合、適用条件、未確認事項、知識項目3 v1、原文を示す。
3. 聞き取り記録2「照合用の計器も、校正が有効か確認する必要があります。」から更新案を作る。
4. これは行動前提であり「校正が有効だった」という観測ではないこと、承認前の通常検索へ入らないことを示す。
5. 人が承認し、v2とKB改訂番号を示す。
6. 「新しい会話」で質問履歴だけを空にする。
7. 同じ主質問からv2、新しい出典、校正状態は未確認という表示を確認。

時間不足時は処理を止め、「検索から体験」の確認済みv1サンプルへ明示的に切り替える。失敗した実行を成功したように説明しない。
